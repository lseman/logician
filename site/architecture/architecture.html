System design

How Logician is built

A TypeScript monorepo arranged as a fan-in: a dependency-free protocol and a lean agent engine form the foundation, feature packages build on the engine, and the terminal UI pulls everything together into one running process.

01 — Package map

Nine packages, one process

Everything runs locally in a single Node process. No services to orchestrate — packages are TypeScript workspaces, not network boundaries.

02 — Dependency shape

A fan-in, not a stack

Package dependencies converge on agent-core and agent-protocol, with the terminal UI composing the complete runtime:

tui
agent-blocks
autoresearch
eoh
agent-core
agent-protocol
  • agent-protocol has zero dependencies — the versioned, dependency-free client protocol every runtime and client speaks.
  • agent-core depends only on agent-protocol. It's the runtime foundation: loop, harness, hooks, compaction, tool registry, context engine.
  • agent-blocks, autoresearch, and eoh each build on agent-core; agent-blocks also depends on rag for retrieval-backed tools.
  • memory, rag, and agent-eval stand alone — no internal @logician/* dependencies of their own.
  • tui sits on top of everything: agent-core, agent-blocks, agent-protocol, autoresearch, and memory.
03 — Package detail

What each package owns

@logician/agent-protocol
The dependency-free client protocol. Zero internal dependencies — the true foundation.
  • Versioned, UI-ready notification envelopes.
  • Internal provider, hook, and tool events are translated before crossing this seam — clients depend on this package, not core internals.
@logician/agent-core
Lean agent engine: loop, harness, hooks, compaction, tool registry. Depends only on agent-protocol.
  • core/harness and core/execution drive the turn loop: intake → model call → tool execution → hooks → next turn.
  • core/hooks — pre/post-tool hook chains, budget tracking, hook metrics.
  • core/compaction — context compaction, run checkpoints, and recovery when a session approaches its token budget.
  • core/session — the append-only thread ledger, file checkpoints, and cloud-sync exclusion markers.
  • core/tools — permissions, tool-call parsing, the tool registry.
  • Internally layered core → capabilities → infrastructure → adapters → application; product composition lives at the application edge.
  • Backend abstraction over any OpenAI-compatible API, with typed, retryable errors.
@logician/agent-blocks
Optional feature modules layered on agent-core: task tracking, user prompts, subagents, and reasoning strategies.
  • tasks/ — todo tracking with status transitions.
  • interaction/ — structured prompts back to the user mid-turn.
  • delegation/ — child-agent spawning, isolated worktrees/context.
  • reasoning/ — SSR, Tree of Thoughts, Graph of Thoughts, Reflexion, Best-of-N, Self-Consistency, Auto-CoT, In-Context CoT, plus a shared base + registry.
  • rag/ — retrieval-backed tools, the one place this package depends on @logician/rag.
  • Re-exports @logician/eoh as one more opt-in reasoning strategy.
@logician/eoh
Evolution of Heuristics (arXiv 2401.02051) — a standalone evolutionary optimization engine.
  • Population management, evaluator, and compaction for evolving heuristics across generations.
  • Own session logic, persistence, and dashboard.
  • Wired directly into agent-core's application layer, and re-exported by agent-blocks. Opt-in, not on the critical path.
@logician/autoresearch
Measured experiment loops: run, evaluate, keep or discard against a baseline.
  • Depends only on agent-core to drive experiment trials.
  • Ported from pi-autoresearch; used for reproducible improvement loops rather than one-off runs.
@logician/memory
Persistent, SQLite-backed memory. Stands alone — no internal @logician/* dependencies.
  • Observation capture, consolidation, and lexical + semantic retrieval.
  • Context injection back into the agent loop.
  • Exposed to any MCP client via @logician/memory-mcp (apps/memory-mcp), independent of the TUI.
@logician/rag
Hybrid retrieval. Stands alone — consumed by agent-blocks, not the other way around.
  • Dense + BM25 hybrid search with structural chunking and cross-encoder reranking.
  • Query rewriting, source attribution, and context budgeting.
@logician/agent-eval
Outcome-grounded evaluation runner for agent trials. Stands alone.
  • Treats repository state and executable checks as authoritative.
  • An agent's own completion claim is retained only as diagnostic evidence, never as the pass/fail signal.
@logician/tui (apps/tui)
The terminal UI. Streams model output, tool traces, and reasoning live to any VT100-compatible terminal — local, SSH, or tmux. Composes agent-core, agent-blocks, agent-protocol, autoresearch, and memory.
  • layers/presentation — rendering pipeline.
  • layers/input — keybindings, input bar, steering queue.
  • layers/theme — theme system, theme selector.
  • layers/events / layers/core — event plumbing, TUI core state machine.
  • components/ — status bar, transcript display, MCP manager, reasoner selector, EOH panel, popups/overlays.
  • Entry point handles exec and doctor CLI modes before booting the interactive TUI.
04 — The turn loop

Inside the harness

Every turn moves through the same pipeline, whether it's a plain chat message, a tool call, or a subagent delegating back to its parent.

  • Task scope and intake — initializes the registry, result cache, system prompt, and task status, then drains steering at turn boundaries and follow-ups when the agent would otherwise become idle.
  • Provider pipeline — context transforms run before transport conversion; request and payload hooks can modify provider options, and thinking, text, and tool-call deltas stream as ordered events.
  • Recovery and compaction — retryable provider failures use bounded retry; context-full failures compact to a target budget and retry. Proactive compaction also runs while preparing a later turn.
  • Tool batches — each call is prepared and permission-checked before internal and user hooks run. Parallel-safe calls execute concurrently around sequential barriers, while result messages retain the model's original order.
  • Loop or finish — context accounting, diagnostics, refreshed configuration, and queued messages can continue the loop. Stop policies, acceptance verification, optional reflection, and structured task status determine the final run outcome.
05 — Outside the process

The tool bus

Everything the agent can touch outside its own process goes through a typed tool call — visible, loggable, and gated by the permission mode.

LLM backend
Any OpenAI-compatible API — local (llama.cpp) or hosted, swappable with a single config change.
MCP servers
stdio and streamable-HTTP transports via agent-core/capabilities/mcp.
SearXNG
web_search / web_fetch against a local or remote SearXNG instance.
Filesystem · Git
bash, ripgrep-backed grep, fd/find-backed find, and git status/diff/log.
Logician
Local AI agent framework for code, research, and reproducible workflows.
